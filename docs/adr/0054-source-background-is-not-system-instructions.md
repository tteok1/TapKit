# ADR0054：历史与记忆原文不进入系统指令层

- 日期：2026-10-17
- 状态：accepted
- 任务：P02-03真实编辑/分支验收中发现的共享上下文缺陷修复

用户把已发送问题改为“只回复编辑分支成功”，新分支、新问题、当前来源指针均正确，旧分支/账本保留；真实响应仍是“未执行工具”。公开引用元数据表明该轮自动召回5条旧用户指令，2条包含此前工具诊断的“未执行工具”。源码将history.background和memory.background原文与可信产品规则一起拼入系统消息。数据标签不能代替角色隔离；这是明确的优先级装配缺陷，与本次现象吻合，但不据元数据单独保证模型为何选择该答复。

ContextService.prepare按模块ID将history.background/memory.background从systemModules中分离，保留模块ID/来源原文，用JSON包装为一条背景user消息，固定放在显式接续背景之后、本轮消息之前。最后的实际用户消息保留原文与顺序；产品规则、工具权限、显式项目/个人指令的既有相对顺序不变。历史和记忆仍按原权限/删除/版本/相关性选择，不关闭功能、不扩大授权，也不删改真实历史。

背景user消息作为pinnedMessages交给既有assemble，计入同一token估计、root剩余量和模型窗口；压缩/重装配继续保留该背景和当前用户消息。资料内的伪标签/旧命令仍处于JSON数据和user角色，不能生成system/developer角色或额外工具授权。工具结果仍使用原生配对的tool角色，不通过此路径转换。

上下文来源快照的prompt_version记为原提示版本加source-data/1，区分装配策略；基础prompt资源正文未修改。没有IPC/DB迁移、native存储schema/绑定版本、账户、工具定义/选择策略、预算/重试或依赖变化。普通ChatRunner本来按当前canonical重组，不加载旧native前缀；既有专用native验收能力不修改。

新增两项直接上下文回归验证记忆/历史均不占system、原文/来源仍保留、当前用户最后且预算计数增长；真实HistoryService编辑→ChatService→ModelRouter→智谱Adapter→SQLite的合成回归注入跨会话旧诊断，并检查实际序列化消息角色、旧分支和来源引用保持。固定传输按是否错误提升旧指令产生不同合成答复，作为可重复缺陷探针，不模拟真实LLM服从率。三项先红后绿，再运行相关上下文/记忆/分支/工具检查。

真实复验仅由用户在修复构建中再编辑原主分支提问一次；旧失败证据与所有已通过范围保留，不能把工程通过当实机回答已恢复。其他渠道/协议仍暂缓，不把本修复当P04新功能验收或扩到P05。证据见docs/evidence/P02-03/live-2026-10-17/edit-observation-2026-10-17.json及background-priority-fix-2026-10-17.json。
