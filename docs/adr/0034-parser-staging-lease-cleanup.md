# ADR 0034：解析暂存目录的租约清理

日期：2026-10-09。状态：accepted（实现中）。

解析前在Core生成的tmp/ingest/<ID>内写独占标记，包含profile、目录ID、fileVersionId、jobId和lease epoch/owner，不保存原件路径。原件仍在不可变blob中。后台清理只处理本profile、有合法标记且对应file.parse载荷的旧目录；当前running租约即使已到期也保留，直到正常worker回收/释放。不同版本、未来epoch、缺job或无法辨认的目录均保留。

每轮最多查看200个根条目，每个候选树最多4000节点/16层。标记通过只读固定句柄最多读取4096字节，读后核验身份/长度和时间；删除前再次检查目录、标记字节和租约。所有路径先解析为绝对路径并确认属于具名暂存根，检查真实路径/regular类型并拒绝根或子树junction/symlink，才递归删除。不会进入原件blob目录、外部目录或未知目录；无有效旧标记的历史暂存不自动删除。

核心就绪后发起后台扫描，每60秒维护，避免阻塞连接提示。扫描串行共用当前promise；退出时停止新扫描/遍历并等待当前操作，再关闭数据库。清理失败保留待处理状态，仅输出固定诊断，不输出用户路径。

五项合成集成覆盖实际终止当前FileParser进程（在注入executor处暂停，尚未启动helper）、SQLite重开后当前/过期租约保留和正常回收后的删除、并发维护、未知/损坏/异profile/错版本标记、过深树、根/嵌套junction及停止后不访问已关闭Store。源字节与托管blob不变。测试适配器和仓库runtime-lock复制在独立fixture根；不依赖会被构建重写的产物，不执行合成适配器，也不把该验收当成AppContainer成功。
