# ADR 0061：原生复制通道与紧凑附件卡片

- 日期：2026-10-23
- 状态：采用；本地验证结果见对应 progress/evidence，不提升原 live/gate
- 范围：P02-02，关联 P03-01；ui_fix 当前工作区

## 问题

消息、代码和表格图标调用 navigator.clipboard.writeText，但桌面 Host 拒绝 Web 权限请求，导致按钮无法写入系统剪贴板。旧 UI 测试替换浏览器接口，只验证了传入文本，漏掉真实桌面权限路径。聊天附件还用一整行来源、按钮和多个说明段落占据输入区。

## 决策

1. 复用既有 tapkit.copyText / tapkit:copy-text。共享 UI 通过 ClipboardProvider 注入桌面原生写入，消息、Markdown 代码/表格、选区复制共用有成功/失败反馈的图标。不放开 Web 剪贴板权限，也不增加 Renderer 的读取能力；顶层可信 sender 校验保持。
2. Host/preload 共用 ClipboardTextSchema：最多 2,000,000 个 UTF-16 单元，与最大草稿一致。完整校验，不 trim、不截断，超限报错且不覆盖剪贴板。消息保留原 Markdown，代码保留正文空白；Shiki 不再在最后一行额外插入换行。表格使用 TSV，空列保留，单元格内制表符/换行/引号按引号转义，公式只取一份 TeX，不把 KaTeX 双层 DOM 重复复制。原 KaTeX 安全显示链路保持。
3. 复制实测通过正式 preload/Host 写入并读取系统剪贴板、实际粘贴到输入框。测试专用 STA 进程先将原剪贴板的全部可获取格式保存在内存，结束恢复；不把用户原剪贴板内容写文件或日志。
4. 输入聚焦保留中性边框，使用轻柔外阴影过渡，支持深色/缩放/减少动效。附件统一为圆角文件卡片，图片同样用文件图标；文件名下显示类型、已知大小和真实上传/解析/就绪状态。删除底部常驻说明，预览可点名称，下载/重试在更多菜单，移除按钮 hover/键盘聚焦显示，触摸设备常显。附件条横向滚动；小窗口按缩放约束顶部控件高度并缩小空输入高度，确保发送区可达。
5. 单文件关闭使用既有 files.cancelImport(selectionToken)，不取消同批其他文件。每个 File 有独立 AbortSignal；即使关闭时导入已经提交但回执尚未送达，关闭项也不重新加入草稿。已提交原件保留在文件库；无路径兼容上传同样排除迟到引用。首次发送等待解析期间关闭材料，也必须从最终发送引用排除；移除同步保存草稿。整页导航取消仍保留此前已提交项到原会话草稿，不改变原权限、固定版本和解析就绪门槛。

## 不变与验证边界

无数据库迁移、Core/Provider/翻译逻辑修改，无图片理解/OCR扩展。保留已有工作草稿、三模式共用草稿、临时会话和跨导航处理。单元测试验证长度/TSV/单文件取消竞态，相关集成覆盖聊天与文件生命周期，Electron 验证真实复制/粘贴、公式、附件关闭、预览下载、导航与布局。实际命令、失败记录及生产恢复写入 docs/evidence/P02-03/clipboard-attachments-2026-10-23。
