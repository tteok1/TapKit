# ADR 0087 · 嵌入推理退出 Core 事件循环

- 日期：2026-11-23
- 状态：采用

CI #120 在与已通过的 #119 相同实现上测得流式 P95 107ms，超过 100ms 门槛。协作式分块修正了连续分词阻塞，但锁定的 onnxruntime-node 1.24.3 在 `setImmediate` 回调中同步调用原生推理，返回 Promise 没有将计算移出当前事件循环。真实 BGE 对比中，直接推理期间事件循环 P95 40.63ms；调整线程自旋未改善，因此保留原有 2/1 计算线程配置。

默认本地嵌入使用一个按需启动的 Node Worker，仅接收有界 token 窗口并返回 CLS 向量。模型仍从锁定本地目录读取，父线程先核验完整模型字节；分词、查询前缀、384/64 窗口、归一化和加权仍共用原实现，模型 revision 不变。直接 BGE 入口保留用于向量一致性和性能对比。计算线程是可信 Core 的执行线程，不提供额外工具、存储接口或安全隔离权限。

每个推理窗口都关联独立请求。取消立即结束对应等待，迟到向量被丢弃，不影响其他调用。一个已进入原生计算的窗口可以完成，但取消后不再安排后续窗口；索引仍在 Core 中复核取消、资料作用域与版本，最后原子发布。Worker 退出或缺失不回退为同步推理，后续新请求可重新建立共享服务。

空闲计算线程不阻止进程退出；Core 关闭时显式终止全部嵌入线程并拒绝未完成请求。测试文件和联合负载夹具也显式清理共享服务。构建将固定 Worker 文件复制到 Core 产物目录，开发目录包含该产物，包内和端到端测试验证实际加载路径。

真实模型回归核对普通文本、查询前缀、跨窗口 Unicode 文本的 token 数、revision、维度和完整向量；本机最大分量差为 0。另覆盖单调用取消、另一个根继续、初始化中关闭、异常退出、迟到响应和共享服务重开。平台完整负载仍以新的 CI 与新包实测为准，规格机与真实资源门禁不变。

依据：[ONNX Node 1.24.3 实现](https://github.com/microsoft/onnxruntime/blob/v1.24.3/js/node/lib/backend.ts)，本地锁定包 `onnxruntime-node/lib/backend.ts`；[线程管理说明](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。
