# ADR 0080 用户审阅后的 GitHub 发布

2026-11-11，P09-03。

每个工作绑定一个 GitHub.com 仓库。连接验证登录账户、规范仓库名、仓库 ID 和默认分支，并由 Host Vault 按资料配置和工作 ID 加密保存细粒度 PAT。读取、推送和创建 PR 的本地许可独立检查。Core 在受信网络调用期间使用凭据。Renderer 只读账户和许可信息。断开请求一经接收便挡住待派发的写入，并删除 Vault 条目。

从默认分支浅克隆到新建的私有 bare 镜像。刷新基准在准备工作区前执行，使用新镜像验证成功后才替换原映射。Git 只接收固定 HTTPS 远程和结构化分支，使用临时环境配置注入凭据，关闭重定向、外部 hooks、全局和系统配置、凭据助手及递归 submodule。镜像的自有配置按允许项检查。工作区沿用既有文本、大小和路径限制。REST 使用同一网络政策，固定 `api.github.com`、API 版本 `2022-11-28` 和 User-Agent，限制响应大小。Git 凭据配置见 [Git 官方文档](https://git-scm.com/docs/git-config)，Draft PR 和检查接口见 [GitHub REST 文档](https://docs.github.com/en/rest/pulls/pulls?apiVersion=2022-11-28)。

提交说明从修改文件生成，用户可以编辑。提交、推送和创建 Draft PR 各自生成一次性审阅票据，绑定窗口、任务版本、账户、目标、源码或提交及有效期。提交只使用已接受且通过当前源码测试的文件。私有索引写入快照字节并按原 head 更新工作分支。推送核对远端基准包含本地基准，目标只限该工作的分支。旧远端 head 校验结合祖先检查，只允许创建分支或快进。

沿用 `worktrees.state_json` 保存推送和 Draft PR 回执。远端写入前先保存待核对记录。响应丢失时，推送查询准确 ref 和 SHA，Draft PR 按仓库 ID、base、head、SHA 及本工作标记核对。未知结果保留到重启后的查询，用户可以继续核对。PR 链接由已验证的仓库和编号生成。读取检查或评论缺权限时显示数据范围。

验证使用 P09-03 集成、单元和桌面测试。真实 GitHub 验收使用 R07 单独授权的测试仓库和 PAT，运行命令和资源处理记录见任务交接。
