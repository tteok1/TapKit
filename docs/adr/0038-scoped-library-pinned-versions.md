# ADR0038：资料库范围视图遵守固定版本引用

状态：2026-10-09 已采纳；P03-01仍在实施，真实原生解析验收未完成。

需求审计复现：项目引用固定旧版本，但 files.list 一直联接文件库 current_version_id，格式筛选、大小排序和正文搜索也读取最新版；下载按项目旧引用鉴权时会拒绝该列表给出的新版。详情的“另存副本”未传versionId，同样会复制库中最新版。问题由真实SQLite集成测试复现，属于P03-01的版本/引用管理，不等到后续检索阶段处理。

项目/会话范围的默认get/list统一选择该owner的固定版本：优先显式source引用，其余有效角色按更新时间与ID稳定选择，保持每文件一个卡片。库范围保持current版本。JOIN同时检查版本所属file/profile和未删除状态；缺失、无版本或指向其他file的引用不能回退到库中新版。显式versionId仍由原有checkScope再鉴权，不扩大任何grant。

范围视图按所选版本返回格式/MIME、大小与内容读取状态，格式筛选和正文搜索使用同一版本，大小排序也按该版本。文件逻辑名称、revision、currentVersionId仍反映共享实体；version.name保留该版本的原始名称，界面明确显示“此范围固定版本”及原始文件名。没有新建同义表、迁移或DTO。

随后审计复现：files.folder_id为共享实体的目录，直接用于范围根目录筛选会隐藏已引用的文件，接收范围也无法进入其他owner的目录。指定owner的get/list现在统一投影目录：只保留本profile中未删除且属于该owner的目录，否则显示在该范围根目录；会话没有目录，统一在根目录。library同样将项目目录中的文件投影到库根目录。未指定owner的内部元数据仍返回共享物理父目录；引用不会移动实体，明确移动仍更新共享父目录/revision。显式访问外部目录继续拒绝，删除目录不使关联文件从根列表消失，不自动创建第二套目录关系。实际SQLite复现及Electron引用/移动/导航/下载证据见 docs/evidence/P03-01/scoped-folder-checkpoint-2026-10-09.json。

原件和结构读取在I/O后继续检查固定owner/version；范围固定旧版可容忍库中另建新版，撤权或重新绑定版本仍拒绝结果。普通库的默认current读取继续在并发替换时冲突，显式历史读取不变。未绑定有效版本的旧引用须从文件库显式重新引用，不自动扩大权限。

详情复制显式传当前查看versionId，副本名称需保持该版本的扩展名；不匹配时说明并禁用复制，重命名仍可操作。重命名/收藏/恢复返回的是实体当前版，因此UI完成操作后重新读取当前owner的视图，防止显示漂移；关闭详情后的晚到响应由既有序号拒绝。恢复新增库版本，当前范围固定引用继续保持原版。

验证包括不同格式替换、旧/新正文隔离、source/input多引用稳定选择、项目/会话范围、错误版本指针拒绝、默认读取并发替换与I/O后重新绑定拒绝。实际Electron覆盖范围内格式筛选、旧原件下载、复制、元数据操作和恢复。合成结构提交不等于native worker验收；本机受阻helper与真实模型未运行。结果与故障记录见 docs/evidence/P03-01/scoped-library-checkpoint-2026-10-09.json。
