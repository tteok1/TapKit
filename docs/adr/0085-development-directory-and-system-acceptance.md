# ADR 0085 · P11-01 开发目录与分层验收

- 日期：2026-11-13
- 状态：采用

`pack:dir` 延续现有的独立目录和运行时打包入口。P11 开发目录携带完整的编译产物、工具运行时、源码及 SHA-256 清单。包内重新执行当前用户隔离探测，能力回执由本地机器与 Windows 身份校验。来源证据和用户 profile 不进入开发目录。安装与升级沿用 P11-02。

普通 PR 和 push 使用无凭据工程流程。独立 Windows 作业运行当前用户原生探测、标准用户验证、Office 和应用安全回归。`live.yml` 仅接受受保护 main 的手动触发，并绑定独立环境。R02–R05 固定请求目标，凭据仅注入 API 验收执行步骤。R01、R06、R07 和 R08 仍走各资源的专用验收入口。

常规工作模型请求携带已授权的资料和按会话权限选取的记忆与历史。资料仍通过既有固定引用进入，路由保持订阅与 API 同一逻辑请求和根预算。记忆与历史由 `MemoryService.background` 选择，再复用聊天的背景数据封装，作为本轮目标之前的 user 消息传递，不进入系统指令；编程和研究入口沿用各自上下文范围。封装后的背景计入工作输入预算。

`eval:agent` 使用 Vitest 实际运行和检索独立 golden scorer，记录离线 60 例和同预算委派的观测结果。生产语义与工具成功率需真实模型和校准人工评分，报告保留空值直至验收。

Core 在数据库、备份、清理和消息入口初始化后报告就绪。Windows 原生校验与普通界面操作并行，仍检查完整运行时路径、字节与报告绑定的用户身份。校验期间启动信息返回 `SANDBOX_UNAVAILABLE` 和原因 `PROBE_IN_PROGRESS`。解析、Office、代码与终端在校验通过后才可启动，等待期间响应取消。校验失败或超时关闭原生能力，Core 退出会中止校验。

项目检索以批量读取核验固定资料版本、索引代数、过期状态和删除墓碑。向量和全文排序在 SQLite 中预筛已授权的版本组合，候选仍逐条核对原文定位及内容哈希。聊天流式持久化沿用有界批处理，刷新间隔为 32 毫秒。流式文本提交后主动唤醒 outbox，并保留每 30 毫秒的兜底分发；后台任务领取仍每 100 毫秒轮询。
