# ADR0036：聊天材料读取固定版本的解析结构

状态：2026-10-09 已采纳；P03-01仍在实施，原生解析验收待R15恢复。

此前 ChatService.material 对 ready 文件直接 UTF-8 解码原件，PDF/Office即使已有解析结果也不能成为聊天材料。改用 FileRepository 从固定 fileVersionId 读取已验证的结构块，最多100000字符，合并前计算上限；不在Host解析二进制文件或执行表格公式。结构缺失、状态已变化、parserVersion不一致、需要OCR或无文本块时明确失败，不能改为原件文本回退。原件仍由受控下载链路处理。

P02历史文本附件保留严格UTF-8兼容路径，只限已支持的文本扩展并拒绝NUL/超限；普通二进制文件即使元数据误标ready也不进入该路径。新inputs.attach为其受控托管原件新增固定版本的当前session引用，保证项目会话内的旧文本/粘贴材料可读。此入口仍只对旧文本做即时兼容，物理文件的完整P03导入体验尚需统一到Host选择token。

项目聊天材料必须有本会话或当前项目的明确固定引用；ID本身不扩大项目权限。读取前后检查session/project状态、项目变更、文件删除及引用撤回，变化时拒绝陈旧结果。inputs.references默认只列当前项目/会话授权的固定版本，库中新版不会替代项目旧版；普通聊天保留显式选择本profile文件的行为。不新增P03-03项目索引或P04检索功能。

ResourceRef/Locator和ChatMaterial DTO保持现有契约。全文件结构块可供当前聊天和files.read使用，原文本选区兼容；PDF矩形、sheet/code/slide定位交互仍属于P03-02，不以此文本消费实现冒充预览/选区验收。

测试用合成受信结构经真实租约提交验证消费端，没有运行原生Office/PDF解析或真实模型。覆盖历史版本、禁止原件读取、项目固定引用、撤权/删除/作用域变化、旧文本与字符上限；既有聊天/文件页Electron回归与失败记录见docs/evidence/P03-01/material-checkpoint-2026-10-09.json。
