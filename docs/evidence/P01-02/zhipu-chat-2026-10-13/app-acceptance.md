## 用户操作

1. 打开“设置 → 模型连接 → API Key 账户”。选择“OpenAI 兼容”和“OpenAI Chat Completions”；标签填写`Zhipu App FlashX 2026-10-13`，Base URL填写`https://open.bigmodel.cn/api/paas/v4`，modelId填写`glm-4.7-flashx`。在密码框输入Key并保存，观察Key框清空；点击该账户的“检测”一次，记录文本/工具是否成功。上次Key仅在CLI进程内使用，因此此次需要在应用内输入并加密保存。
2. 在“模型与用量”设置范围选“默认”，首选模型选该账户的FlashX，勾选“仅此模型，不自动切换”，回答方式选“快速回答”（思考关闭），回答长度选“简短”，保存设置。其余预算保持默认；不启用付费后备。返回普通聊天，新建会话。
3. 首轮发送`本次测试口令是蓝鲸731。只回复收到。`；第二轮发送`刚才的测试口令是什么？只回复口令。`。确认逐段显示、回答口令正确、显示实际模型为FlashX。等待本轮回答和自动标题等后台活动完成。
4. 从托盘或应用退出入口完全退出，使用同一启动命令重开。确认账户凭据仍存在，无需重新输入Key；打开同一会话，第三轮发送`请再次只回复本会话的测试口令。`。确认历史仍在、口令正确；这只能初步证明用户可见续聊，是否实际复用了加密native引用由后续本机元数据核验确定。
5. 最后发送`请逐行列出1到100，每行一个数字。`，看到输出后立即点击“停止回复”。记录是否停止、部分回答是否保留。打开“模型与用量 → 用量账本”，记录实际模型、actual/estimated、输入/输出及失败/取消记录；等待后刷新，再重启检查同一记录未重复。

这是一次连接检测和四次聊天发送；正常应用仍可能产生自动标题等辅助调用以及既有有界重试。不能把它视为CLI的六请求上限。问题出现时停止后续步骤并提供错误码/发生步骤，不重复发请求。停止阶段可能没有供应商最终usage，应保留未知/估算，不要求显示0；自动标题等辅助用量也须纳入同一root，不能只按前台消息次数算总账。
