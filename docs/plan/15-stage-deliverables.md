# 阶段交付物、验收深度和收口标准

本文补充01的摘要。每阶段3—4项任务；阶段是交付边界，会话是执行容器，一个阶段可以由多个会话完成。以下标准与任务详规同时生效，不用阶段摘要代替任务测试。

## 通用收口规则

每项任务达到以下条件才允许收口为实现完成：纳入需求有真实代码/入口；约定接口/迁移/默认值一致；正常与必需异常分支跑过；规定验证有真实证据；交接与需求状态已同步。只写UI、只写接口、只生成脚手架、只写测试文件、只跑mock，都不能代替相应的实际完成条件。

| 阶段状态 | 含义与后续动作 |
|---|---|
| not_started / in_progress | 尚未开始 / 有任务进行中 |
| engineering_passed_external_pending | 规定本地实现与检查通过，仅缺明确外部资源live；可继续使用已验证接口，不算正式验收完成 |
| passed | 本阶段规定实现/检查/所需真实验证/交接均齐全 |
| failed | 存在必需实现、数据、隔离、安全或测试缺口；先修责任任务，不把技术失败冒充缺账号 |

完成一个编号任务后更新它的交接；阶段最后一个任务结束时执行本节对应组合验证，写docs/progress/Pxx-gate.md。阶段收口不是必须另找人批准的流程；Codex执行验证并报告结果，用户可随时体验和提出修改。缺资源须保留清单，后续资源到位补测更新状态。

接口层依赖可以接受上游implemented_not_live_verified，前提是所用接口本地实现与测试确实完成并在交接列明；依赖OS隔离、迁移保全和权限边界时必须拿到真实证明。当前依赖未满足只能做可隔离的实现准备，不得将下游验收标通过。
