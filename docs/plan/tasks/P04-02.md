# P04-02 上下文预算、压缩检查点与缓存

## 任务摘要与前置条件

让长会话在有限窗口内保留最新目标、精确约束和未完成调用。

前置：[P04-01 中文混合检索、重排与引用证据](P04-01.md)、[P01-03 模型目录、费用账本和自动后备](P01-03.md)

执行前按[阅读地图](../16-reading-map.md)定位P04-02行，只读本任务需要的共享章节；阶段验收见[阶段收口](../15-stage-deliverables.md)的P04部分。新会话先核对实际docs/progress/CURRENT.md、INDEX.md与当前交接；不要重新通读整个目录。

## 需求与边界

策略04/05/10/25；产品08长会话摘要可查看纠正。

- FR-08-011（实现）：长会话生成上下文摘要，支持查看和纠正。
- FR-08-012（实现）：新会话接续已有会话摘要，选择保留哪些背景。

## 代码位置与输入输出

主要变更：packages/context/{assembler,budget,checkpoint,cache}、resources/prompts、tests/evals/compaction。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. 按可信产品规则→模式/工具→项目规则→任务状态→相关记忆/证据→近期对话和当前消息装配，实际role序列由provider转换。规范序列化稳定前缀，动态时间/trace放后部或metadata。
2. 每次请求计算输入+输出预留+模型独有推理占用+下一工具结果+安全余量。已包含输出的reasoning不再扣；可用模型tokenizer优先，未知用UTF-8字节保守上界，不用“字符/4”估算中文。
3. 达有效预算65%评估外置/精简；80%停止加入大结果；压缩后目标≤50%。checkpoint字段按原策略goal/constraints/decisions/completed/active/next/artifacts/evidence/open_questions/execution_refs保存，原始事件可查。
4. 保留未完成工具配对、批准中动作、最新纠正、精确ID/金额/日期/否定条件；写入前Zod、来源范围、引用存在和关键literal校验，失败最多重试一次，仍失败沿用旧有效状态并缩小可重新检索的证据。
5. 初版原生compaction只为已验证provider能力启用，其余应用检查点可工作。跨provider不得迁移opaque块；业务cache key含scope/权限版本/来源版本，删除/撤权使缓存失效。最终答案语义缓存默认不做。
6. 摘要查看/纠正生成用户修正事件，更新下一轮taskVersion，不直接篡改供应商opaque状态；摘要是索引/状态而非唯一真相。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

T12/T03：连续3次压缩前后精确约束集合100%保留；压缩时pending/批准状态可恢复；换模型小窗口自动重新预算；撤权后cache命中也不能读旧资料；统计实际缓存量，不以配置成功当命中。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P04-02（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。
