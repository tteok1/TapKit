# P08-02 深度研究工作流与来源核验

## 任务摘要与前置条件

把搜索、项目资料和持久工作组织成有提纲、证据和可导出报告的研究任务。

前置：[P08-01 匿名浏览器交互与用户接管](P08-01.md)

执行前按[阅读地图](../16-reading-map.md)定位P08-02行，只读本任务需要的共享章节；阶段验收见[阶段收口](../15-stage-deliverables.md)的P08部分。新会话先核对实际docs/progress/CURRENT.md、INDEX.md与当前交接；不要重新通读整个目录。

## 需求与边界

产品18.2、10工作；本版不依赖外部应用连接，来源为公开网页和本地资料。

- FR-18-009（实现）：设置研究主题、范围、用途与交付格式。
- FR-18-010（实现）：选择公开网页、上传文件和已连接应用作为来源。
- FR-18-011（实现）：查看、修改研究提纲与计划。
- FR-18-012（实现）：查看研究进展、已读来源和阶段发现。
- FR-18-013（实现）：中途补充方向、排除来源或提前结束研究。
- FR-18-014（实现）：获取包含结论、依据、引用和局限的报告。
- FR-18-015（实现）：对指定结论继续查证，补充或更新报告。
- FR-18-016（实现）：导出报告与来源清单。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. ResearchSpec包含topic/questions/scope/dates/includeDomains/excludeDomains/localVersions/outputFormat；默认计划3-6个子问题，用户可调整并中途steer。
2. 每个子问题检索最多3轮，全部任务最多40个实际读取来源、搜索8次；根budget先约束。记录搜索query、读过来源、支持/反对证据和缺口，而非仅保存摘要。
3. 来源去重用canonicalURL+contentHash，时间敏感结论携带访问/发布日期；冲突分别引用，不投票当真。引用验证器检查sourceId存在、原文片段支持指定claim，模型评分只能补充。
4. 输出报告结构为问题/结论/依据/方法与范围/局限/来源表，默认中文MD+DOCX/PDF可选；研究报告里的推断明确标识，不将生成文字当检索来源回流。
5. UI显示简短阶段发现和已读来源，可排除来源/提前结束。提前结束为partial并生成已验证部分，不标完整研究成功；后续查证新run继承来源版本引用。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

5个研究fixture涵盖多源冲突、无法访问、时间条件、用户中途排除来源、无答案。T09/T13：每个引用必须真实读过，关键结论有独立证据，排除后的来源不能继续用于新结论；预算内完成并导出可读报告。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P08-02（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。
