# P11-02 Windows安装包、升级与标准用户验证

## 任务摘要与前置条件

形成无需用户手工准备运行环境的Windows x64安装包。

前置：[P11-01 系统评测、故障回归与源码开发版交付](P11-01.md)

执行前按[阅读地图](../16-reading-map.md)定位P11-02行，只读本任务需要的共享章节；阶段验收见[阶段收口](../15-stage-deliverables.md)的P11部分。新会话先核对实际docs/progress/CURRENT.md、INDEX.md与当前交接；不要重新通读整个目录。

## 需求与边界

用户25的后续安装包目标，产品02/30桌面更新与36恢复。

- 支撑共享架构/策略，不对应单一UI复选项；详见本任务需求与全局测试。

## 代码位置与输入输出

主要变更：electron-builder.yml、scripts/package-runtime.ps1、resources/runtime、tests/install、docs/distribution。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. NSIS per-user安装到LOCALAPPDATA/Programs，DATA与安装目录分离；打包所有锁定runtime/模型/字体、helper与第三方许可。asarUnpack仅native module/helper/runtime需要的文件，不把secret/demo用户数据打包。
2. 安装后首次运行检查资源hash、SQLite ABI、helper和Office能力；错误显示具体组件及修复/重新安装入口。无模型凭据时仍可用本地功能，不预置公共API key。
3. 建立版本metadata、更新检查和手动下载安装流程，更新源使用配置的GitHub Release HTTPS和hash；正式自动安装仅对可信签名/manifest可验证包启用，不执行远程更新脚本。GitHub不可达时正常离线使用。
4. 更新前安全暂停任务并备份数据库，安装文件原子替换；schema升级失败回滚应用与快照，不回滚用户最近已明确删除的数据墓碑。较旧包不能打开更高schema写入。
5. 卸载默认保留DATA，用户明确勾选清除时展示范围并清理应用自有目录；不删除用户原仓库或外部导出文件。标准用户无需UAC，运行时不修改系统Python/Git关联。
6. 签名由R11提供，未签名只能标开发测试包。体积/磁盘指标按架构文档，网络断开/中文路径/杀进程/升级均做验证。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

T21：干净Win11标准用户，无Node/Python/Git/Office安装，完成聊天配置、本地解析、Office生成、代码测试；升级保数据和版本；安装中断恢复；卸载保留/清除两分支；验证签名(若有)/sha256和包内无secret。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P11-02（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。
