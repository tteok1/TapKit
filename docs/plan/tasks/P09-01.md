## 技术实现步骤

1. Host选择目录授权后检测Git根、当前分支、HEAD、dirty状态；Git broker先为此code_project创建DATA内私有bare镜像(复制对象、禁用hardlink与alternates)，再从镜像在DATA/workspaces创建worktree，分支tapkit/<task短ID>。不从用户原仓库直接建立共享.git的linked worktree。镜像路径仅Core/broker可读写，不给执行沙箱Git元数据权限；固定git.inspect/commit工具通过broker操作并核对映射。非Git目录创建托管副本并记录来源，不执行隐式git init。
2. dirty仓库默认基于HEAD建worktree，并提示未提交修改未带入；用户勾选带入时复制已检测的tracked diff和明确选中的untracked文件，保留排除规则和hash；不stash/reset用户目录。
3. 代码树读取排除.git/node_modules/依赖cache/secret常见目录，文件引用支持行号；精确路径授权再校验，AGENTS.md只提供项目规则，不扩大工具权限。
4. applyPatch要求baseHashes，对修改文件创建快照和diff；冲突返回上下文，不盲目覆盖。用户接受/撤销单文件只修改该worktree，恢复同时校验当前hash，不做无条件git reset --hard。
5. Diff UI显示新增/修改/删除、行号、左右侧评论与反馈；评论转后续task输入绑定path/baseVersion。任务结束保留worktree直到用户明确清理，不能自动删未交付成果。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。
