# P06-01 持久化工作任务、计划和执行编排

## 任务摘要与前置条件

把聊天的执行底座扩展为带目标、依赖、预算和验收的工作任务。

前置：[P05-03 聊天版本端到端验收](P05-03.md)

执行前按[阅读地图](../16-reading-map.md)定位P06-01行，只读本任务需要的共享章节；阶段验收见[阶段收口](../15-stage-deliverables.md)的P06部分。新会话先核对实际docs/progress/CURRENT.md、INDEX.md与当前交接；不要重新通读整个目录。

- FR-10-006（实现）：选择直接执行或先查看计划。
- FR-10-007（实现）：查看、修改、删除、重排计划步骤。

- FR-10-009（实现）：设置时间或用量上限，达到上限后通知用户。
- FR-10-011（实现）：查看待开始、排队、运行、等待输入、暂停、完成、失败、取消状态。

## 代码位置与输入输出

主要变更：packages/core/orchestrator、packages/workflows、apps/desktop/src/renderer/features/work、migrations/0006_work.sql。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. 实现Task/TaskVersion/Run/PlanStep和共享状态机；ChatRunner与WorkRunner复用底层Provider调用、账本和事件，不建立第二套消息/权限系统。一个task可有多run，终结run不可原地改回running。
2. 工作创建收集goal、受众/格式/数量、资料、验收、期限/预算；缺少必须事实时user.ask。默认复杂任务显示简短计划并自动在授权范围内执行；用户planFirst开启则先waiting_user待接受计划。
3. PlanStepInput固定stepKey/title/dependencies/inputRefs/outputContract/acceptance/optional。最多12步，可拆近期里程碑；依赖图拓扑检查拒绝环；执行指定步骤时自动纳入其必要依赖并在UI显示。
4. 主循环读最新taskVersion/取消/预算→取可执行step→装配→模型/工具→登记结果→确定性验收。模型“完成”只发完成候选；产物存在/测试/引用等验收失败回到同step修复，最多2轮。
5. 支持运行中steer：新要求先写event和taskVersion；旧计划未派发动作停止，复用已有产物需验证相关性；旧版本返回只归档不能覆盖新版本。
6. 工作列表/看板按项目、状态、模型/内置角色筛选，显示排队容量、计划、工具过程、阶段成果、耗时、用量、等待输入。暂停/接受成果等动作数据接口先对接，恢复细节在P06-03完成。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

T13：计划含环被拒，选步骤包含依赖；简单工作不无谓规划；goal修改后旧step不可继续派发；模型假称完成但文件缺失不能completed；partial/failed/cancelled区分；同会话并发请求正确排队。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P06-01（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。
