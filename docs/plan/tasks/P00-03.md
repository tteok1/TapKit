# P00-03 Windows隔离与文件运行组件验证

## 当前方案补丁（2026-09-30；基于旧方案实测问题优化，现以本补丁为标准）

当前路线由 Windows AppContainer 承担任务隔离：Node、Python、ConPTY 与受控 Office 转换使用每次独立 profile/SID、runtime/input/workspace 最小 ACL、Job Object 和无网络 capability。OfficeWorker 采用 LibreOfficeKit unipoll/runLoop 适配；Git 使用可信 GitBroker 的固定 Win32 操作及私有快照，不要求在 AppContainer 内运行 MinGit。无需初始化 TapKit 专用 Windows 账户、持久账户凭据或账户级 WFP 规则。account.execute / CreateRestrictedToken 路径及其 KnownDlls/Kernel32 失败仅作历史对照，不是当前执行前置。

P00-03 必须把已验证兼容适配正式接入，再完成 T07/T08/T19 所需的路径、只读输入、越界访问、网络、宏/外链、Job 取消、并发和中断恢复验证，并在独立标准用户下验收。失败关闭；不得以普通宿主进程代替 AppContainer。现有 LOK/会话盘符实验不等于生产集成，能力保持 failed、P00-gate 保持 failed，直到全部验收通过。

> **以下正文保留 2026-09-24 专用账户方案及原任务要求，作为历史版本；与上方补丁冲突时以上方为准。**

## 技术实现步骤

1. 实现共享隔离契约中的helper启动协议、账户/受限令牌/ACL/Job Object/内核网络规则/输出管道及持久恢复；先只提供诊断执行器，不对用户开放任意shell。所有runtime来自runtime-lock，运行目录只读，任务目录可写。
2. 用最小Node/Python脚本读取授权input、写output、spawn子进程，验证取消杀整个树；记录账户/令牌、网络规则、Job限制和进程退出结果。输入路径必须经过handle规范化和reparse检查。
3. 在受限环境运行LibreOffice headless转换DOCX/XLSX/PPTX→PDF，指定每job私有UserInstallation目录，宏和外部链接禁止。验证中文字体、无Office预安装环境；原件不修改。
4. 验证GitBroker固定status/diff及恶意配置/环境拒绝，执行通道验证ConPTY交互；凭据与网络必须仍不可达。兼容失败只补必要运行库/明确ACL，不开放整个用户目录。
5. 提供capability probe结果给Core：nativeExecution/officeRender/terminal分别标available/failed和具体错误。失败能力有依赖门禁，聊天开发不受牵连；不能改用无隔离process.spawn偷偷通过。
