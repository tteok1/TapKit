## 需求与边界

用户答复07/08优先；不是包装Codex运行时，也不是通过Codex CLI执行任务。

- FR-02-004（实现）：绑定 API Keys / OAuth 登录其他 agent 的订阅服务（先支持 Codex 的）

## 代码位置与输入输出

主要变更：packages/providers/codex、apps/desktop/src/main/auth、resources/catalogs、tests/{integration,live}/codex。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. 按模型接入文档注册pi公开provider，注入每account独立CredentialStore。认证界面先做开发诊断路由，后续P02接到正式设置页；token不进入Renderer状态树。
2. 实现login/auth events、system browser打开、state/PKCE验证、取消、端口占用恢复、device-code/手工回调入口。采用上游login，不自行伪造client_id；不读取现有Codex账号文件。
3. 接入pi SSE流，转换为ModelEvent，maxRetries=0由应用统一负责。记录HTTP错误原始code到脱敏ProviderError，不能只解析人类错误文本。完整assistant工具调用结束才发tool_end。
4. 原生消息/推理签名按模型/账户/adapterVersion加密保存，用应用systemPrompt与tools；provider返回的可变partial即时快照。request abort关联run取消信号。
5. 从发布包目录加载候选模型，连接检测标记真实权限；没有账号时界面显示未配置。提交发行包integrity、接口fixture和源码版本对应说明。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

mock覆盖OAuth取消/错误state/刷新竞争/token轮换、SSE中文拆包/工具参数分片/无done断流。R01到位后测试真实文本、两轮会话、工具echo、重启后凭据刷新、注销；没有R01只标未live，不能将此渠道删出首发。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P01-01（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。
