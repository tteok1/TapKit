# P11-03 GitHub开源交接与官网下载准备

## 任务摘要与前置条件

整理可公开维护的仓库、版本资产和静态下载页面源码，发布地址留作外部资源接入。

前置：[P11-02 Windows安装包、升级与标准用户验证](P11-02.md)

执行前按[阅读地图](../16-reading-map.md)定位P11-03行，只读本任务需要的共享章节；阶段验收见[阶段收口](../15-stage-deliverables.md)的P11部分。新会话先核对实际docs/progress/CURRENT.md、INDEX.md与当前交接；不要重新通读整个目录。

## 需求与边界

用户1/25开源与最终官网客户端；本任务不是Agent生成网站的公网发布能力。

- 支撑共享架构/策略，不对应单一UI复选项；详见本任务需求与全局测试。

## 代码位置与输入输出

主要变更：LICENSE、THIRD_PARTY_NOTICES、SECURITY.md、docs/releases、website、release-manifest.json、.github/workflows/release.yml。

输入为前置任务已验证的接口、用户授权范围和fixture；输出为本任务真实运行的模块、迁移/契约变更、自动测试和验收证据。字段与状态使用共享契约，不新建同义表或第二套run状态。该任务不要求一次实现引用文档内所有后续功能。

## 技术实现步骤

1. 主代码MIT，逐项核对pi/字体/LibreOffice/Git/ONNX的第三方许可与源码提供要求，记录版本和来源；仓库提供贡献、问题模板、支持平台、隐私说明和负责任漏洞报告入口。
2. 发布工作流由人工tag触发，固定Windows构建、hash/SBOM/签名检查、测试报告；GitHub repo/owner来自R10配置，不自动选择当前会话可访问的无关仓库。公开前扫描历史/样本/二进制不含secret和私人材料。
3. 静态官网源码只含产品简介、截图、Windows系统要求、版本、安装包下载、源码/文档链接和隐私说明；品牌/域名配置集中替换。R10/R12未给时下载按钮禁用并标待配置，不填假链接；不部署服务器。
4. release-manifest固定version/platform/arch/url/sha256/signatureStatus/minOS/releaseNotesURL，客户端更新读取同一数据；镜像仅接受同hash资产，不自动信任第三方下载站。
5. 形成维护手册：升级依赖/模型目录/提示词/模板时跑对应回归，出现订阅协议变更先禁用channel并发布兼容修复；长期版本记录不可被替换为latest。
6. 准备完毕后在用户指定仓库/发布资源内执行已授权发布；没有目标或签名资源则交付源码和待发布资产，明确资源阻塞，不虚构已上线官网。

## 异常处理与恢复

遵循共享ErrorCode、事务、幂等和生命周期规则。UI保留已输入/已生成内容，提供具体恢复动作。未知副作用不能盲目重试；安全/权限/版本校验失败不降级绕过。需要尚未配置外部资源时引用[资源ID](../11-external-todos.md)，只阻塞关联live验收。

## 测试与验收

从新机器按README构建；静态官网所有已配置链接实际可达并hash匹配；未配置链接不暴露给用户可点击下载；公开包无隐私数据、许可证齐全，release manifest与安装包版本一致。R10-R12状态单列。

执行pnpm check、与改动相关的unit/integration，以及pnpm test:e2e -- --grep P11-03（纯基础模块可由同标签integration覆盖）；涉及真实服务再执行对应test:live。命令和结果必须来自真实运行，测试命名包含任务ID。

## 完成与交接

- 上述需求对应的界面/接口真实可用，无可点击“假成功”；迁移可重跑且历史数据保留。
- 测试和故障分支达到本任务条件；影响既有功能时补相关回归，不无故重复无关全套测试。
- 将变更、测试命令/退出码、证据路径、未完成资源项写到docs/progress/P11-03.md，更新需求追踪状态。
- 依赖契约有变化必须同步shared docs/类型/fixtures；不把技术选择留给下一任务猜测。
- 仅占位任务按“状态页可用、底层不可调用”验收，不宣称延期能力已实现。
