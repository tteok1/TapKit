# 每项任务的最小阅读地图

本表是导航，不要求一次通读。先按taskId定位一行；编号02—12指对应共享文档编号，§指该文档的章节。遇到缺失契约可以追加读取，但说明当前要解决的问题；不得为了少读而漏掉适用要求。

## 每次如何读取

1. 根AGENTS、CURRENT、INDEX以及当前任务交接；同会话已有且未变的内容不重复加载。首次会话或范围变化时读取02-decisions全文。
2. 当前tasks/Pxx-yy.md全文，当前阶段15中的一节；本表该行列出的共享章节。
3. 前置任务只读接口/验收/遗留部分，需要实现细节时再定位代码。原始references、完整09矩阵、整个plan-index.json和旧日志不作为启动必读。
4. 用rg定位标题、任务ID或符号，再按范围读取；遇到截断继续分段，不把截断当已读全。长日志落盘，只读失败摘要和相关上下文。
5. 每个任务将实际用到的资料路径/章节写入交接。进入新会话以最新代码和记录核对，不能依赖旧对话的隐含知识。

## 工作记录分工

- CURRENT：当前接续点，目标≤1,200汉字，保留少量路径，不堆运行日志。
- INDEX：37项任务和12阶段的简短状态表。
- 每任务交接：当前实现细节、验证证据和下一步；只读取相关任务。
- docs/evidence：完整日志/截图/报告；按需查询。
- requirements.csv：逐条验收覆盖；按当前owner_task或requirement_id过滤。

这些大小和读取频率是本手册的工程约定，不是对Codex模型token上限的测量。
