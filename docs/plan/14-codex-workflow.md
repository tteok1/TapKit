# 怎样用 Codex 执行这份手册

本次补充版本：1.1。推荐流程：手册保存在项目磁盘目录 → 精简项目指令 → 每次领取一个任务 → 完成实现和测试 → 写进度与交接 → 下一会话读取状态接续。

## 1. 目录会不会撑爆上下文

把文档保存在项目目录，是让Codex能按需读取；把几十个文件全文一次性贴进消息，是把它们直接塞进当前上下文。建议前一种。目录中有多少文件，不等于每轮模型请求都必须包含多少文件。附件、打开的文件、历史对话、工具读取结果可能进入上下文，具体取决于使用入口和当前配置；不要要求它“先完整阅读整个目录”。

Codex会读取适用范围内的AGENTS.md项目指令，因此这里提供的是短入口模板，详细规格仍留在普通Markdown。官方文档也说明项目指令有单独的大小限制；该限制不等于模型整个上下文窗口。[OpenAI Docs：AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

不要依靠一个无限延长的聊天记录保存项目状态。接续信息存到仓库文件，再由新会话核对实际源码。下面的“一任务一会话”是本项目的使用建议，不是Codex产品限制，也不需要改模型上下文参数。

## 2. 第一次怎样放文件

在Windows选择一个新的项目目录，例如D:\projects\TapKit，把完整手册的内容放到该目录的docs/plan/下。不要把项目源码写进手册的tasks/目录。

~~~text
TapKit/                       ← 在Codex打开这个本地项目根目录
  AGENTS.md                       ← 首次提示词让Codex从模板合并/创建
  docs/
    plan/
      00-START.md
      01-timeline.md
      ...                         ← 其余规格原样保留
      tasks/P00-01.md
      codex/AGENTS.template.md
      execution-state/             ← 初始状态种子，只用于首次初始化
      templates/
    progress/                      ← Codex实际持续维护，不重复覆盖
      INDEX.md
      CURRENT.md
      RESOURCES.md
      requirements.csv
      P00-01.md                    ← 开始该任务时创建，结束时补交接
      P00-gate.md                  ← 阶段收口时创建
    evidence/                     ← 真实日志、截图、报告
    adr/                          ← 重要技术决定及理由
  apps/ packages/ native/          ← 从P00起创建的源码
~~~

在Codex里打开这个本地项目，以项目根目录为工作目录；使用能执行本地代码的开发会话。Windows原生隔离和安装验证必须在Windows运行，不能把其他系统的通过结果替代它。

默认不并行启动多个会话修改同一工作目录。不需要把整个ZIP作为聊天附件；解压到磁盘后告诉Codex入口路径即可。已有项目中保留原AGENTS.md和进度记录，只合并需要的规则，不能重新初始化覆盖已有代码。

## 3. 直接复制：第一次启动

先完成上面的目录摆放，然后发送：

~~~text
请在当前项目根目录开始开发TapKit。开发规格位于docs/plan/，这是实现请求，不是重新编写开发计划。

先只读docs/plan/00-START.md和docs/plan/codex/AGENTS.template.md：
1. 根目录没有AGENTS.md时，从模板创建；已有则保留现有规则并合并适用内容。新创建后在本次会话显式读取，不假设自动重载已经发生。
2. docs/progress不存在时，从docs/plan/execution-state复制初始记录；已存在的同名文件绝不覆盖。初始化不是完成开发任务。
3. 按docs/plan/16-reading-map.md中P00-01的行读取当前任务和相关共享契约，不递归通读整个手册，不加载references原件或全部任务全文。

本次范围只完成P00-01：实际创建工程、准备锁定依赖、启动并运行规定测试。请自行解决手册已授权的常规技术问题；先核对目录和已有文件，保护现有改动。只完成本任务及其必需修复，不提前开发后续业务功能。

结束前必须更新docs/progress/INDEX.md、CURRENT.md和P00-01.md，记录实际变更、命令/退出码、证据、未完成项和下一任务。测试没运行不能写通过。缺外部资源就记录准确阻塞，继续本任务不依赖它的部分；不要因此重问已经确定的产品或技术选择。

最终告诉我：本任务状态、怎么启动或验证、测试结果、交接文件和下一步。完成本任务后收口，不自动启动全部37项任务。
~~~

## 4. 直接复制：继续下一任务或新会话接手

在同一个项目目录中发送。新会话不用复制旧聊天全文：

~~~text
继续开发TapKit。以当前仓库代码和docs/progress为实际状态，docs/plan为规格。

先读根AGENTS.md、docs/progress/CURRENT.md和INDEX.md，以及当前未完成任务的交接记录。核对工作目录、分支/HEAD、未提交改动和已有测试证据，不能仅凭记录声称代码已完成。

若有未完成任务，接续该任务；否则选时间线中依赖满足的下一任务。本次最多完成一个编号任务。按docs/plan/16-reading-map.md读取该任务的最小资料，不通读所有文档或旧日志。已实现但缺live凭据的任务按记录保留，允许继续依赖其已验证本地接口的工作；原生隔离/安全测试未过不能当作依赖已满足。

执行实现、规定测试和必要修复，结束前更新INDEX.md、CURRENT.md、当前任务交接记录和requirements.csv相关行。如果这是阶段最后一个任务，同时按15-stage-deliverables.md完成该阶段收口并记录Pxx-gate.md。不要重写计划，不自动切到下一阶段。
~~~

INDEX/CURRENT互相矛盾时，先查对应代码/测试/最近交接，修正文档；没有完整记录但有代码时接管核验，不能重建覆盖。新会话若打开的是另一工作树，先确认目标提交和必要文档已在该工作树，不假设旧目录的未提交改动已复制。

## 5. 直接复制：中途收口，准备换会话

~~~text
请在最近的安全边界收口当前任务，准备换一个Codex会话继续。
不要开始新功能。保留现有代码，记录正在运行的命令/进程及处理结果，避免新会话重复执行尚未核对的操作。
更新docs/progress/CURRENT.md、INDEX.md和当前任务记录：已完成到哪、具体剩余步骤、修改文件、分支/HEAD和未提交状态、测试命令与结果、失败原因、下一步第一条操作、需要读取的最少文件。
未完成就保持in_progress或准确阻塞状态，不为交接把任务改成完成。不要为了整洁删除未提交代码、reset工作区或编造commit。最后给我一句新会话可直接使用的接续提示。
~~~

不必等到明显遗忘或上下文耗尽再记录。每次完成可验证子步骤、发现阻塞、改变关键决定、以及每次结束回复前都更新记录；意外中断时允许从上次checkpoint与当前代码恢复，不保证最后一条未落盘推理可恢复。

## 6. 直接复制：阶段验收

~~~text
请核验docs/progress/CURRENT.md标明的当前阶段，不启动下一阶段。
只读取15-stage-deliverables.md的对应阶段、该阶段任务验收章节及相关交接/测试证据。将实际源码和运行结果与每项交付标准核对，修复属于本阶段的缺口，并执行受影响的必要验证。
生成或更新docs/progress/Pxx-gate.md（Pxx替换为实际阶段编号），列出交付文件/入口、逐条验收结果、阻塞项、真实测试证据和下一阶段可用接口。同步INDEX.md、CURRENT.md和相关需求行。
只允许passed、engineering_passed_external_pending或failed等真实状态；mock不能替代live，文档存在不能替代功能可运行。最后给我可操作的检查步骤和阶段结论。
~~~

可选：明确希望同一会话连续做一个阶段时，把任务数量限制改成“当前Pxx阶段，按依赖逐项做完并收口，不进入下一阶段”。较大的阶段仍建议拆会话；换会话不要求重新规划或重新问产品需求。

## 7. 我应该查看哪些文件

| 你想知道 | 查看 |
|---|---|
| 现在做到哪、下步是什么 | 实际项目docs/progress/CURRENT.md |
| 37项任务总体进度 | 实际项目docs/progress/INDEX.md |
| 某项任务改了什么、是否真测过 | 实际项目docs/progress/Pxx-yy.md |
| 这个阶段交付到什么程度 | [阶段交付和收口标准](15-stage-deliverables.md)与实际Pxx-gate.md |
| 缺哪些账号/测试资源 | 实际项目docs/progress/RESOURCES.md |
| 原需求是否实现并有证据 | 实际项目docs/progress/requirements.csv的相关行 |

当前交付中的execution-state全部是未开始状态，表示应用尚未开发。以后以项目docs/progress为活记录；更新手册时不把种子再次覆盖进去。

官方提示建议说明目标、必要上下文、输出和边界；本手册提示词进一步固定了项目范围、验收证据和交接位置。[OpenAI Docs：提示](https://learn.chatgpt.com/docs/prompting)
