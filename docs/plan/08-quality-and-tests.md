# 测试、评测和发布验收

## 1. 统一命令

P00-01创建以下根脚本，不能在任务结束时只写“建议测试”。具体框架文件放tests目录，所有测试能指向专用TAPKIT_DATA_DIR，禁止使用开发者日常数据。

| 命令 | 固定职责 |
|---|---|
| pnpm bootstrap | 依照lock准备开发依赖、运行时和本地fixture |
| pnpm dev | 先编译Storage/Core，再启动Electron+Core+Renderer热更新，监听main/preload及providers/tools；不重复编译原生helper（ADR 0010） |
| pnpm build:desktop / pnpm test:dev | 桌面分项构建 / 真实双击与dev入口、同profile重启、正常退出冒烟；不替代完整build或原生安全验收 |
| pnpm check | typecheck + lint + 包依赖方向 + schema/manifest验证 |
| pnpm test:unit | Vitest单元，固定时钟和种子 |
| pnpm test:integration | 真实SQLite/文件/helper/本地mock HTTP，无供应商密钥 |
| pnpm test:e2e -- --grep Pxx | Playwright测试开发构建，按任务标签过滤 |
| pnpm test:live -- --provider all | 真实五模型/搜索/GitHub可选子集，显式读取本机测试凭据 |
| pnpm test:security | 注入、IPC、路径、网络、审批、数据删除隔离 |
| pnpm test:recovery | 进程kill、磁盘错误、重复事件、未知副作用、租约失效 |
| pnpm test:perf | 标准数据集、Windows性能采样，生成P50/P95和内存报告 |
| pnpm eval:agent | 固定离线/真实任务集，输出结果与费用，不泄露思维链 |
| pnpm build / pnpm pack:dir / pnpm dist:win | 编译 / 可运行目录 / NSIS用户安装包 |
| pnpm docs:check | 需求→任务→测试映射、链接和证据完整性 |

开发E2E可保留测试所需检查入口，正式构建必须移除；通过构建标志而非运行期secret开关控制。正式安装包另做独立黑盒冒烟，不通过开启远程调试来“修复”生产权限限制。Playwright Electron支持具有实验性，锁定版本并保留基础启动回归。[Playwright官方文档](https://playwright.dev/docs/api/class-electron)

## 2. 分层策略

性能用例归入独立Vitest perf项目，通过pnpm test:perf执行，CI在其他集成worker全部退出后运行；不与原生Office/进程资源压力用例并发争用CPU/磁盘。P02-03仍使用1万会话/10万消息、200页/30次查询及500ms P95断言，普通integration不代替性能验收。

P02-03合成数据建库在beforeAll中单独限时120秒；查询采样用例仍限时60秒，不把建库耗时计入用户查询P95。报告同时记录seedMs/sampleMs及原数据量，写入test-results/P02-03-perf/performance.json随CI归档；本地证据按实际运行另行保存，不自动覆盖旧日期的验收报告。

单元测纯状态机、消息转换、预算、权限匹配、冲突合并；集成测事务、迁移、文件落盘、helper、mock流；E2E测用户闭环；live测真实供应商；eval测不固定工具顺序的最终成果质量。不得以覆盖率替代最终正确性。

所有测试产物进test-results，记录commit/schema/prompt/model/adapter/OS。模型输出使用断言契约和最终结果，不做整段措辞快照。需要UI视觉检查时保留截图和人工核对项。

## 4. 评测集和门槛

在P00建立固定目录，P04/P06逐步补足。最终保留集至少60例：普通聊天10、文件/检索15、记忆/压缩10、工作/恢复10、浏览器/研究5、编程5、注入/授权5；安全测试另有更完整确定性集合。每例包含输入、fixture哈希、期望结果、不可接受行为、独立评分器、最大预算。

硬门槛：确定性安全/权限/副作用防重测试100%通过；关键状态恢复测试100%通过；被引用的定位可打开率100%；不得用平均成功率抵消一次真实越权。文本回答任务语义通过率≥90%、工具工作完成率≥85%、有答案检索Recall@20≥90%、引用支持率≥95%；无答案集虚构来源=0。发布前逐项展示样本量和误差，不把小样本当普遍保证。

自动评分先用代码断言；语义采用经人工校准的rubric。首次60例全部人工复核评分器，以后抽查20%和所有失败。API真实可用性受外部服务影响，单独报告应用正确处理率，不把供应商停机简单算作实现完成。

子Agent默认仅对独立研究分支开启：对同一10例、同根预算测试单/多Agent各3次；有≥10%完成时间改善且质量不降、费用倍率≤1.5才默认启用自动委派，否则保留手动/显式委派并默认单Agent。数值是本产品初始门槛，不是行业结论。

## 5. 性能验收

设备基准：Windows 11 x64、4核/8线程、16GiB、NVMe、无独显。数据：1万会话/10万消息、2,000文档/20,000chunks、2个并发根任务。

本地冷启动≤5s；热启动≤2s；空闲总应用内存≤700MiB；聊天+索引≤2GiB；重工作总峰值≤4GiB。会话列表/本地搜索P95≤500ms；混合检索P95≤2s；收到上游文本后显示P95≤100ms；取消指令持久化≤200ms、新派发停止≤1s。第三方首字延迟单独测量，不将其承诺为本地SLA。

解析/嵌入等后台任务降低优先级并让出CPU；任意大文件不能阻塞Renderer超过100ms。导入边界失败给错误，不静默截断成成功。

## 6. 阶段门禁和证据

每任务结束记录docs/progress/<taskId>.md：变更摘要、需求ID、测试命令及退出码、截图/报告路径、实际未完成项、下一依赖。必须附真实命令结果，不由模型生成“全部通过”的样例。

P05为聊天演示里程碑；P11-01为完整开发版本门禁；P11-02安装包门禁。缺少live凭据可标implemented_not_live_verified继续独立开发，但正式宣传五渠道可用必须全部live通过。未实现的占位页测试“不可触发真实动作”，不能计为底层能力完成。
